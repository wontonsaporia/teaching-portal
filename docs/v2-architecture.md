# Teaching Portal v2 — 学習セッションと情報設計（草案）

更新：2026-10-11。**v2試作ブランチ専用。mainには未導入。**

## 決定事項

- 教材閲覧・ドリル・模擬テストは登録不要で公開する。
- ゲストは認証・パスワードを求められない。ゲストの回答・進捗・履歴は**タブ単位の `sessionStorage`** に保存し、ページ移動・再読み込み時も継続する。
- 通常のタブ終了でゲスト履歴は破棄される設計。ただしブラウザのセッション復元機能や複製タブでは復元・コピーされる場合があり、「閉じれば必ず完全消去」とは保証しない。ユーザー操作による「今すぐゲスト履歴を消去」を必ず設ける。
- ローカル学習プロフィールは端末内でAES-GCM暗号化して保存し、パスワードで解錠する。メールアドレス・電話番号・外部ログイン・クラウド学習履歴データベースは設けない。
- 現在の `default` IDの暗号化データを**ゲストとして扱わない**。旧データと暗号化鍵／パスワードの対応は不変に保ち、解錠・バックアップ・移行確認の後にのみ移行する。
- ゲスト／プロフィール間で回答履歴を混在させない。移行はユーザーの明示操作を要し、移行完了前にゲストデータを消さない。

## 画面の境界

1. **START** — ゲストで始める、学習プロフィールを選ぶ、新しい学習プロフィールを作る。教材への公開直リンクは塞がない。
2. **HOME** — 「最近の続き」を優先。ゲスト時は一時記録であることを明示。プロフィール時は解錠後の履歴を表示。
3. **LIBRARY** — 公開教材を教科・問題集・単元で閲覧。
4. **PRACTICE** — 1問ドリルと50問模擬テスト。問題バンクIDを保持。
5. **PROGRESS** — 解答履歴、初回・直近正答率、苦手単元への導線。ゲストは当該タブの記録だけを表示。
6. **SETTINGS** — プロフィール名変更、暗号化バックアップ、復元、ゲスト履歴の消去と明示的な移行。

既存の `materials/care/*.html` への直接URLは維持し、保存処理を抽象化してから段階的にページを移す。PWAによって古いスクリプトが残る可能性があるため、サービスワーカーを含め更新順を検証する。

## データ所有・鍵管理

- `guest`: `sessionStorage` の `teaching-portal-guest-v2:*` のみ、メール・パスワードなし。非暗号化なので共有端末では内容を端末操作者が読み取れる。
- `local-profile`: プロフィールIDでスコープされた暗号化保管庫。パスワード紛失時の復号を保証しない。名前等のメタデータは暗号化対象外。
- `legacy-default`: 移行対象の**既存プロフィール**。移行完了まで現在の鍵・保存キーを維持。ブラウザストレージ全体削除は禁止。
- `backup`: 明示的なパスワードで暗号化したエクスポート。ゲスト→プロフィール移行は解錠後に検証して確定。旧バックアップの平文JSONは警告後にインポート可能。

**実装注意:** `sessionStorage` はタブごとに見えてもブラウザ復元時の残存例があり、機密データの削除保証には用いない。またPWAのService Worker/Cache Storageはユーザー回答をキャッシュしてはならない。

## ゲスト機能の受け入れ条件

- [ ] ゲストで試験を開始でき、パスワード画面が出ない。
- [ ] 同じタブ内のページ移動／再読み込みで回答・進捗・学習分析が残る。
- [ ] ゲストと解錠済みプロフィールの回答記録は相互に混ざらない。
- [ ] 「ゲスト履歴を消去」でゲスト用の保存キーだけを削除し、暗号化された旧`default`を触らない。
- [ ] 新プロフィール作成時のゲスト記録移行は明示的な同意、暗号化保存、復号照合後にだけ完了。
- [ ] タブを閉じた場合の挙動と復元例外を、Chrome/Firefox/Safariの実機で確認。
- [ ] 暗号化バックアップ作成・誤パスワード・復元失敗・旧データ引継ぎをE2E検証。
- [ ] 公開サイトへの変更はPRレビュー・検証後にのみ反映する。
